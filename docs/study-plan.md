# Two-Week Study Plan — Associate Consultant / Consultant Developer

## Schedule and starting point

Plan for **4 hours a day, 5 days a week, for 2 weeks**. Since you already know Python, use Java as your main language to learn the role’s stated programming-language requirement. Your **German C1 proficiency meets the language requirement**; use it as a strength in interview practice rather than spending study time on language basics.

## Practice project

Build a small **P&amp;C claim-intake REST API** in Java. Keep it as a learning project, not a production insurance system. Use mock data to accept a claim, validate required fields, retrieve a claim, and update its status. Add unit tests and a CI workflow.

## Week 1 — Build software fundamentals

* **Day 1 — Agile, Git, and user needs:** Turn a simple customer claim-intake need into user stories and acceptance criteria. Practice commits, branches, and pull requests.
* **Day 2 — Java and OOD:** Translate familiar Python logic into typed Java. Practice classes, interfaces, collections, exceptions, encapsulation, and separating responsibilities.
* **Day 3 — REST and insurance context:** Build basic claim endpoints. Learn HTTP, JSON, status codes, and the role of policy, billing, and claims systems in P&amp;C insurance.
* **Day 4 — Implementation and debugging:** Add validation and clear error handling. Make a small change request and debug it systematically.
* **Day 5 — Unit testing and quality:** Write JUnit tests for normal and invalid cases. Review readability, edge cases, and what your tests do—and don’t—prove.

## Week 2 — Practice delivery and consulting

* **Day 6 — Code review and collaboration:** Review your changes as a teammate would. Explain a technical choice, respond constructively to feedback, and document the solution.
* **Day 7 — CI/CD:** Configure a pipeline to build and test on changes. Understand what should block a merge and how continuous delivery differs from deployment.
* **Day 8 — Cloud and customer trade-offs:** Learn AWS service categories and basic cloud concepts. Practice explaining security, reliability, and cost trade-offs without building a production deployment.
* **Day 9 — Responsible AI and data-driven improvement:** Use an approved AI tool to explain an error or suggest tests; verify its output. Track one simple measure (such as test pass rate or time to resolve a seeded bug) and describe one improvement. Use no confidential data.
* **Day 10 — Customer communication and interview demo:** Demo the API in 3–5 minutes. Practice clarifying a customer need, explaining a trade-off in plain language, and giving examples of integrity, teamwork, rational decision-making, and learning from feedback. If useful, rehearse part of the demo in German.

## Daily four-hour routine

* Learn: 50 minutes
* Build: 100 minutes
* Test and debug: 60 minutes
* Review, explain, and plan: 30 minutes

## Priorities

Aim to demonstrate **solid fundamentals and coachability**, not production-level expertise in every tool. Be ready to discuss Agile, Java/OOD, Git, debugging, unit tests, CI/CD, REST, and basic AWS awareness. The job emphasizes customer communication and continuous learning alongside code quality. Guidewire’s systems support the P&amp;C insurance lifecycle; learning the basic policy, billing, and claims vocabulary will help you connect technical work to customer outcomes.

If time remains, explore Guidewire InsuranceSuite terminology, but prioritize the skills explicitly listed in the posting. Be honest about your project being a practice example and explain how you would learn the team’s actual tools and standards.
